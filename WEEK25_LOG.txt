- Real bug found and fixed in the repo (not just the deploy copy):
  data/vindhyachal_soundings.npz was lowercase while candidate_plants.csv's
  entry ("Vindhyachal") and every other plant's sounding file use
  capitalized names. app.py builds the filename dynamically from the
  CSV name, so this is a latent case-mismatch bug that has always been
  silently masked by macOS's case-insensitive default filesystem --
  it would have 404'd the sounding-density panel for Vindhyachal (one
  of the app's two default-highlighted plants) the moment it ran on
  Spaces' case-sensitive Linux filesystem. Fixed with `git mv
  data/vindhyachal_soundings.npz data/Vindhyachal_soundings.npz` in the
  actual repo -- a correctness fix, not a deploy-only workaround.
  Verified no other script hardcodes the old lowercase path (grep
  across *.py, no hits -- app.py is the only reader).
